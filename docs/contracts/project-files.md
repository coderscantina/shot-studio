# Project files contract

This contract owns the files a video consists of and what each one means. `shot-core` implements it: it parses every file from text and writes it back with no IO. The examples below are the files in `fixtures/examples/`, and the `shot-core` tests check that each one parses, writes back byte-identical and stays identical to what this document shows.

## Channel repo layout

```
<channel repo>/
  .gitignore            ignores media/ and .shot/
  brand/
    brand.kdl           the channel's style: fonts, colors, logo, sounds, bookends, rules
    fonts/ sounds/      in git
    media/              bumper videos (ignored)
  formats/<format>.kdl  the channel's copy of each preset, with the format's rules
  videos/
    <slug>/
      video.kdl         status, format, target date, title
      script.md         chapters as headings, beats as bullets
      cut.kdl           the content: chapters, takes, manual cuts, overrides, derived cuts
      format.kdl        the video's style layer: only what differs from its format
      cut.lock          every styled instance, generated by each build, committed, never edited
      elements/<take>.jsonl   the committed facts of each take
      sources/          links, article snapshots, notes (text, in git)
      media/            recordings and b-roll (ignored)
        <take>/         one folder per take, named by its take id
          events.jsonl  cursor and key events, see below
      .shot/cache/      SQLite and rendered chunks (ignored, safe to delete)
      .shot/export/     rendered cuts, caption sidecar, thumbnail (ignored), see ship artifacts
      .shot/ship/       the upload record (ignored), see ship artifacts
```

Content is what the video says: chapters, takes, a person's cuts. Style is how it looks and sounds, pacing included ([0019](../decisions/0019-semantic-video-elements-and-style.md)). Style cascades through layers that map to files, lowest first: the brand's imports, `brand/brand.kdl`, the channel's `formats/<format>.kdl`, the video's `format.kdl`, then an `override` in `cut.kdl` for one element. The edit scopes in the app are these files: only here, this video, this format, the channel.

```
recording ──analysis──▶ elements/<take>.jsonl   facts, committed
                              │
brand/brand.kdl ─┐            ▼
formats/<f>.kdl ─┼─cascade─▶ style rules ──build──▶ cut.lock ──render──▶ cuts
<video>/format.kdl ┘                       ▲        instances, committed, generated
                       cut.kdl ────────────┘
                       chapters, takes, manual cuts, overrides, derived cuts
```

## What each file owns

- **`video.kdl`**: the card on the board. Status is one of `ideas`, `scripting`, `ready`, `recorded`, `editing`, `shipped`. Moving a card rewrites this field and commits.
- **`script.md`**: the spec. `#` is the title, `##` a chapter, a bullet a beat. Beats link to a source in `sources/`. The prompter reads this file.
- **`cut.kdl`**: the content. It references recordings by take id and media time, never by frame index of an output. It holds:
  - the material each chapter uses of each take, as kept ranges, and a person's cuts
  - layout changes, caption style, caption fixes, the music bed, a person's zooms and overlays
  - overrides: what one element gets instead of what the rules gave it, including K and C on the review queue
  - derived cuts (`short`, `x-clip`) as a few lines on top of the main cut
  - until a video is migrated ([migration](#migration-of-todays-nodes)): rule-made removals, the review queue and rule-made zooms and overlays
- **`format.kdl`**: the video's style layer. Any of the format settings (pacing, layouts, caption style, auto-cut thresholds, prompter mode, the product video settings), a `brand` block with the fields that differ, and style rules. It holds only what differs from the channel's `formats/<format>.kdl`, which is the same grammar with every setting present.
- **`brand/brand.kdl`**: the channel's look and sound, and the channel's rules.
- **`elements/<take>.jsonl`**: the facts of a take, written by analysis, read by every build. Builds never analyse.
- **`cut.lock`**: every instance the rules and overrides produced, with the element and the rule that made it, plus the resolved brand and the hashes of the files it draws from. Generated by every build, committed so a diff shows what the export shows, never edited.

## Rules every module follows

- Every UI action that changes the edit becomes a change to one of these files. There is no hidden edit state.
- Files are written in a stable order so a diff shows only what changed.
- `shot-core` parses and evaluates these files with no IO. Unknown nodes are an error with a line number, never silently dropped.
- The cache is derived from these files and media only. Deleting `.shot/cache` loses nothing.
- A rendered chunk's cache key is a hash of everything that affects its pixels: source media ids, ranges, effects, template parameters, format settings and renderer version.

## Common rules for the KDL files

The `.kdl` files use [KDL v2](https://kdl.dev).

- **Strict.** An unknown node, an unknown property, a missing required node, a wrong number of arguments, a type annotation or a bad value is an error. Errors name the file, line and column, for example `cut.kdl:15:46: unknown value ...`.
- **Canonical form.** `shot-core` writes nodes in the order this document lists them, properties in the order shown, four spaces of indent, one blank line between top-level blocks in `cut.kdl`, and a trailing newline. A canonical file writes back byte-identical. A file in any other valid form is accepted and comes back canonical, so the first save may reformat it.
- **Comments are not kept.** Notes about a video belong in `script.md` or `sources/`.
- **Time** is integer microseconds of a take's media time, counted from the start of the take. Canonical form groups digits by three, so `12_500_000` is 12.5 s. Ranges are half-open, `from` is included, `to` is not, and `from` must be before `to`. Microseconds keep the files exact and independent of frame rate; the renderer snaps to the output frame grid.
- **Ids** (take ids, template and parameter names, derived cut names) are lowercase ASCII letters, digits and dashes, starting with a letter. They are written bare.
- **Keywords** (statuses, layouts, styles, rule names) are written bare. Free text (titles, text parameters) is always quoted.
- **No floats.** Percentages and other fractional values are integers in a stated unit, so every value round-trips exactly.

## `video.kdl`

| Node | Value | Required |
| --- | --- | --- |
| `title` | text | yes |
| `status` | `ideas`, `scripting`, `ready`, `recorded`, `editing`, `shipped` | yes |
| `format` | `reaction`, `opinion`, `product-tour`, `tutorial`: the preset `format.kdl` was copied from | yes |
| `target-date` | text `"YYYY-MM-DD"`, a valid calendar date | no |

Each node appears at most once and takes one argument.

```kdl
title "Why we deploy on Fridays"
status editing
format opinion
target-date "2026-11-20"
```

## `format.kdl`

| Node | Value |
| --- | --- |
| `prompter` | `beats` or `full-script` |
| `pacing` | `loose`, `natural` (0.25 s of breath around cuts) or `tight` (jump-cut style) |
| `layouts` | one or more layouts. The first is the default wherever `cut.kdl` sets none, the rest are offered on the 1 to 4 hotkeys |
| `captions` | `word-pop`, `clean` or `off` |
| `auto-cut confidence=<0..100>` | block with one node per rule. Results at or above `confidence` percent apply right away, the rest go to the review queue |

Layouts are `face`, `face-content`, `split`, `content`, `screen`, `face-corner` and `window` (a captured window on a background).

The five nodes above are required and appear once. `auto-cut` holds all six rules:

| Rule | Properties |
| --- | --- |
| `silence` | `on=<bool> min=<time>`: silences at least `min` long |
| `retake` | `on=<bool>`: inline retakes ("the the first") |
| `misspoken` | `on=<bool>`: misspoken words and self-corrections |
| `pause` | `on=<bool> min=<time>`: pauses mid-sentence at least `min` long |
| `filler` | `on=<bool>`: filler words |
| `idle-screen` | `on=<bool> min=<time>`: screen without change for at least `min` |

The four presets ship in `crates/shot-core/formats/` (`reaction`, `opinion`, `product-tour`, `tutorial`) and are copied into a channel's `formats/` and then into each video. This example is an opinion video with tighter thresholds than the preset:

```kdl
prompter beats
pacing tight
layouts face split content
captions word-pop
auto-cut confidence=80 {
    silence on=#true min=500_000
    retake on=#true
    misspoken on=#true
    pause on=#true min=800_000
    filler on=#true
    idle-screen on=#false min=8_000_000
}
```

### Product video settings

Optional nodes after `auto-cut`, in this order. A missing node means its default, so a `format.kdl` without them reads as before. The cursor is drawn from the event log, so every one of them changes after recording without re-recording.

| Node | Value | Default |
| --- | --- | --- |
| `auto-zoom <trigger>... scale=<percent> hold=<time>` | the auto-zoom rule. Triggers from `click`, `typing` and `cursor`, each at most once; none means the rule is configured but off. It writes `zoom` nodes of `scale` percent (at least 100) and at least `hold` long into `cut.kdl`, each with its trigger as `by` | no rule |
| `zoom-motion` | `instant` or `smooth`: how every zoom of the video moves in, out and between centers | `instant` |
| `cursor size=<percent> smoothing=<time> ripple=<bool>` | the cursor's size as a percent of the recorded size (0 hides it), the window its path is averaged over (0 draws the raw path), and a ripple on every click | `size=100 smoothing=0 ripple=#false` |
| `keystrokes` | the keystroke overlay: `off`, `shortcuts` (keys with a modifier held) or `all` | `off` |
| `window padding=<px> corners=<px> shadow=<shadow> background="#rrggbb" frame=<frame>` | how the `window` layout places the captured window: padding and corner radius in output pixels, a shadow of `none`, `soft` or `hard`, the background color, and a device bezel of `none`, `macbook` or `iphone` | `padding=48 corners=12 shadow=soft background="#101418" frame=none` |

`auto-zoom` is a rule like the auto-cut rules: it writes nodes and changes no pixels by itself. The other four reach the renderer, and each enters a chunk's hash only where it draws, see [timeline evaluation](#timeline-evaluation). This example is the product tour preset:

```kdl
prompter full-script
pacing tight
layouts window
captions clean
auto-cut confidence=85 {
    silence on=#true min=600_000
    retake on=#true
    misspoken on=#true
    pause on=#true min=1_000_000
    filler on=#true
    idle-screen on=#true min=3_000_000
}
auto-zoom click typing scale=160 hold=1_500_000
zoom-motion smooth
cursor size=140 smoothing=120_000 ripple=#true
keystrokes shortcuts
window padding=64 corners=12 shadow=soft background="#141821" frame=none
```

### Format layers

A format file is one layer of the style cascade. The shipped presets above set every setting. The channel's `formats/<format>.kdl` starts as a copy of a preset and adds the format's style rules. The video's `format.kdl` holds only what differs from the channel's: any of the settings, a `brand` block with the brand fields it changes (same grammar as [`brand.kdl`](#brandkdl), without `import` and without rules, at least one field), and style rules. Canonical order: the settings in the order above, then `brand`, then the rules. A video with nothing to change has an empty `format.kdl`.

The resolved settings are the preset with the channel's layer and then the video's laid over it, setting by setting. A `layouts` node replaces the whole list. The brand fields and the rules are not part of the resolved settings; the [cascade](#style-rules) orders those. This is the channel's opinion format, the preset plus the rules that replace the preset's auto-cut and auto-zoom behavior:

```kdl
prompter beats
pacing tight
layouts face split
captions word-pop
auto-cut confidence=85 {
    silence on=#true min=600_000
    retake on=#true
    misspoken on=#true
    pause on=#true min=1_000_000
    filler on=#true
    idle-screen on=#false min=8_000_000
}
on silence min=600_000 {
    cut breath=50_000 confidence=85
}
on filler {
    cut confidence=85
}
on pause min=1_000_000 {
    cut breath=50_000 confidence=85
}
on emphasis {
    zoom 112
}
on click {
    zoom 160 hold=1_500_000
}
```

The example video's `format.kdl` softens the pacing, changes the accent, replaces the channel's three pacing rules with rules at 80 percent and more breath, adds a rule for long silences and switches off the brand's punchline pop:

```kdl
pacing natural
brand {
    colors accent="#ff7a59"
}
on silence min=500_000 {
    cut breath=250_000 confidence=80
}
on filler {
    cut confidence=80
}
on pause min=1_000_000 {
    cut breath=250_000 confidence=80
}
on silence min=4_000_000 confidence=50 {
    cut breath=250_000
}
on punchline off
```

## `cut.kdl`

The edit of the main cut as a list of chapters, followed by the derived cuts. Top-level nodes, in canonical order:

| Node | Meaning |
| --- | --- |
| `captions <style>` | optional, overrides the format's caption style. The main cut ships captions as a sidecar file |
| `caption-fixes { fix "<heard>" "<said>" ... }` | optional. Each `fix` replaces a run of transcript words that reads `heard`, ignoring case, with `said` wherever captions are shown, and the replacement takes the matched words' timing. `heard` is unique ignoring case, neither text is empty. Claude proposes fixes as text and a person edits them in Caption fixes, never through a proposal |
| `music "<file>" gain=<dB> duck=<dB>` | optional. A music bed under the main cut and its derived cuts: a file relative to the video folder, its gain, and the gain it drops to under speech. Both are at most 0 |
| `chapter "<title>" { ... }` | zero or more, in output order |
| `override <take> <kind> at=<time> { ... }` | zero or more, see [overrides](#overrides). Canonical order: by take in cut order, then `at`, then kind |
| `short <name> { ... }` | a 9:16 derived cut, reframed on the face |
| `x-clip <name> { ... }` | a 1:1 derived cut |

A `chapter` holds `take <id> { ... }` blocks in output order. A take may appear in several chapters and several times in one chapter. Inside a take block, all times are that take's media time, in canonical order:

| Node | Meaning |
| --- | --- |
| `keep from=<time> to=<time>` | a range that goes into the output |
| `remove from=<time> to=<time> by=<who>` | a removed range. `by` is the rule that removed it (`silence`, `retake`, `misspoken`, `pause`, `filler`, `idle-screen`) or `manual` |
| `review from=<time> to=<time> by=<rule>` | a finding the rule was not sure about, waiting in the review queue. The material plays until a person decides |
| `ignore from=<time> to=<time> by=<rule>` | a finding a person kept: K in the queue, or a restored removal. The rule leaves this range alone when it runs again |
| `layout <layout> from=<time> to=<time>` | a layout for that range. Elsewhere the format's default layout applies |
| `zoom <percent> from=<time> to=<time> x=<px> y=<px> by=<what>` | a punch-in zoom, at least `100` percent. `x` and `y`, together or not at all, center it on a point of the screen track in its pixels; without them the layout picks the center. `by` names what wrote it: `jump-cut`, `emphasis`, `click`, `typing`, `cursor` or `marker`. A zoom without `by` is a person's |
| `overlay <template> from=<time> to=<time> { <param> <value> ... }` | a template overlay. Each child is one parameter: a name and one text, integer or boolean value. Integers are written grouped by three like times, so a parameter in microseconds reads as one. Later overlays draw on top |

`keep` and `remove` ranges together are in order and do not overlap; gaps between them are allowed. `review` and `ignore` ranges are in order, do not overlap each other, and lie inside kept material. `layout` ranges are in order and do not overlap, and so are `zoom` ranges. Overlays may overlap. Template names and their parameters are defined by the [overlay templates](#overlay-templates), not by the grammar: `shot-core` parses any template, and the renderer refuses to export an overlay that does not fit its template.

Auto cut and auto edit write into the take block and leave a trail, so nothing is asked twice:

- A rule's confident finding becomes `remove ... by=<rule>`, an unsure one `review ... by=<rule>`. Cut (C) in the queue turns a `review` into `remove ... by=<rule>`, Keep (K) into `ignore`. Restoring a removal a rule made also writes `ignore`. A manual cut that touches a `review` or `ignore` drops it: the person has decided about that material.
- A rule that runs again, for example after a threshold changed, skips a finding that overlaps a `remove`, `review` or `ignore` of its kind, and still reports new material.
- Jump cuts are not nodes. The pacing places the edges of each `remove`, and the jump is what is left.
- The punch-in zooms the pacing writes carry `by=jump-cut` or `by=emphasis`, auto zoom's carry their trigger, a Z marker's `by=marker`. A zoom rule that runs again replaces the zooms with its own `by` and leaves every other zoom alone.
- Hotkey markers from the [event log](#cursor-and-key-event-log) enter the cut once, when the take is appended: layout markers become `layout` nodes, Z markers `zoom ... by=marker`, B markers b-roll overlays, A markers feed the retake rule and N markers the chapter boundaries.

A derived cut (`short` or `x-clip`) has a unique name and holds an optional `captions <style>` and one or more `clip <take> from=<time> to=<time>` nodes in output order. It uses only material the main cut keeps inside those ranges, with the main cut's layouts, zooms and overlays, and burns its captions in. Its caption style defaults to the main cut's. Every clip's take must appear in the main cut.

A derived cut shows the main cut's own pixels ([0017](../decisions/0017-derived-cuts-from-main-chunks.md)): each frame is a window of the main frame at the same moment, as tall as the main frame, scaled to 1080x1920 for a `short` and 1080x1080 for an `x-clip`, with the captions drawn on top. A Short's window follows the largest face Vision finds in the camera track where the layout shows the camera, and keeps that face inside; elsewhere, and in an X clip, it stays centered. Overlays drawn for 16:9 may be cut off at the window's edges.

```kdl
captions word-pop

caption-fixes {
    fix "lara vel" "Laravel"
    fix "jeep UI" "gpui"
}

music "sources/bed.mp3" gain=-18 duck=-12

chapter "Hook" {
    take t01 {
        keep from=0 to=4_200_000
        remove from=4_200_000 to=5_100_000 by=silence
        keep from=5_100_000 to=12_000_000
        review from=9_800_000 to=10_400_000 by=filler
        zoom 112 from=8_000_000 to=9_500_000 by=emphasis
    }
}

chapter "The rule everyone repeats" {
    take t01 {
        keep from=12_000_000 to=31_400_000
        remove from=31_400_000 to=33_000_000 by=retake
        keep from=33_000_000 to=58_000_000
        ignore from=45_000_000 to=46_100_000 by=pause
        layout split from=20_000_000 to=40_000_000
        overlay link-card from=22_000_000 to=27_000_000 {
            url "https://github.com/coderscantina/shot-studio/pull/1"
            accent #true
        }
    }
    take t02 {
        keep from=0 to=15_000_000
        remove from=15_000_000 to=16_200_000 by=manual
    }
}

chapter "What we do instead" {
    take t02 {
        keep from=16_200_000 to=44_000_000
        remove from=44_000_000 to=45_000_000 by=filler
        keep from=45_000_000 to=70_000_000
        zoom 112 from=50_000_000 to=52_000_000
    }
}

short friday-deploys {
    clip t01 from=5_100_000 to=12_000_000
    clip t02 from=16_200_000 to=44_000_000
}

x-clip the-rule {
    captions clean
    clip t01 from=12_000_000 to=31_400_000
}
```

A product tour needs no layout, cursor or window nodes here, those come from `format.kdl`. Its zooms are centered: two from auto zoom on the click and the typed text, one from a Z marker. Code from git is an overlay template, `code-diff` in this example: the app snapshots the diff of the chosen commit range into `sources/` (a repo and its tags move, a text file in git does not), types it out over the overlay's range, and highlights the line from the moment the voice reaches the phrase. The template owns its parameter names, as every template does.

```kdl
chapter "Search filters" {
    take t01 {
        keep from=0 to=42_000_000
        zoom 160 from=6_200_000 to=8_400_000 x=2210 y=640 by=click
        zoom 160 from=8_400_000 to=11_000_000 x=1480 y=910 by=typing
        zoom 160 from=30_000_000 to=31_500_000 x=1600 y=900 by=marker
        overlay code-diff from=12_000_000 to=26_000_000 {
            diff "sources/query-parse.diff"
            highlight-line 4
            highlight-at 21_300_000
        }
    }
}
```

### Overrides

An `override` changes what the [style rules](#style-rules) gave one element. It names the element by its identity: the take, the kind and `at`, the element's start time. The take must be in the main cut, and each (take, kind, `at`) appears once. Its children, in canonical order:

| Child | Meaning |
| --- | --- |
| `keep` or `cut` | the answer to the review queue, at most one of them. `keep` drops the rule's cut and the review item. `cut` applies the rule's cut whatever the element's confidence, with the rule's breath; without a cut rule it removes the element's whole span |
| an effect node | replaces the rules' effect of the same key for this element. The grammar is the [effect grammar](#effects), the target the element's kind. An overlay is keyed by its template, so `overlay link-card for=6_000_000 { url }` replaces the rules' link card and leaves another template alone |
| `<effect> off`, `overlay <template> off` | removes the rules' effect of that key for this element |

An override changes at least one thing. The build binds it to the element of its kind whose start is nearest to `at`, within 500 ms, so it follows a re-analysis that shifts the element a little. One that finds no element is an orphan: the build lists it in the lock and `shot check` reports it. K in the review queue writes `{ keep }`, C writes `{ cut }`.

The example channel's video, after migration: its take blocks hold the material and a person's cut, the style lives in the layers, and the overrides answer the queue and change single instances. The build reads it together with the [elements](#elements) below into the [lock](#cutlock) below.

```kdl
captions word-pop

chapter "Hook" {
    take t01 {
        keep from=0 to=12_000_000
    }
}

chapter "The rule everyone repeats" {
    take t01 {
        keep from=12_000_000 to=58_000_000
        layout split from=20_000_000 to=40_000_000
    }
    take t02 {
        keep from=0 to=15_000_000
        remove from=15_000_000 to=16_200_000 by=manual
        keep from=16_200_000 to=44_000_000
    }
}

override t01 click at=6_200_000 {
    zoom off
}
override t01 filler at=9_800_000 {
    keep
}
override t01 url at=22_000_000 {
    overlay link-card for=6_000_000 {
        url
        accent #true
    }
}
override t01 pause at=45_000_000 {
    cut
}
override t02 filler at=30_000_000 {
    keep
}

short friday-deploys {
    clip t01 from=5_100_000 to=12_000_000
}
```

## Timeline evaluation

`shot-core` evaluates a project into one output for the main cut and one for each derived cut.

- A main output has one group of segments per chapter. A segment is a kept range of one take with one layout, so a kept range splits wherever a layout change starts or ends. It carries the zooms and overlays that overlap it, with their full ranges.
- A derived output has one group, named after the cut. Its segments are the main segments cut down to each clip's range, so every chunk of a derived cut lies inside one chunk of the main cut.
- Export caches rendered video in chunks. A segment is snapped to the output frame grid and cut at every half second of its take's media time, which is the recordings' keyframe grid. So a chunk is at most 0.5 s and starts on the grid or at a segment edge.
- Each chunk has a content hash (BLAKE3) over the renderer version, the output aspect, the burned-in caption style with the caption fixes (or the fact that captions are a sidecar), the take id and the take's media identity, the frame rate and the chunk's frames of the take, the layout, the cursor and keystroke settings when the layout shows the screen (every layout but `face`), the window style in the `window` layout, the zooms with their scale and center, and every overlay overlapping the chunk with its full range and parameters. Instant zooms are cut to the chunk; with `zoom-motion smooth` every zoom of the segment counts whole, because the easing at one frame depends on where the zoom starts and ends and where the next one centers. Output position, chapter titles, zoom provenance, review items and the music bed are not part of it. Deleting a word therefore re-renders only the two chunks at the new edges, and every other chunk is reused at its new position. A new caption fix re-renders the derived cuts and nothing of the main cut.
- An overlay that names a file (a `code-diff` snapshot, a `b-roll` file) adds the file's size and modification time to the hash of every chunk it overlaps, so a file replaced under the same name renders again.
- A derived chunk renders in two passes. Its base is the main chunk that holds its frames, keyed as above and shared with the main export, so whichever export runs first renders it for both. The derived chunk's own key extends the hash above (with the derived aspect and burned-in captions) with the base chunk's key, which of its frames it shows, the window's position on every frame and the caption on screen on every frame with its highlighted word. A new transcript or a moved face re-renders only the derived chunks whose captions or window changed.
- A take's media identity hashes the size and modification time of its video tracks and of its event log, since the cursor is drawn from events. A take recorded again under a reused id gets a new identity, so it never matches the old recording's chunks.
- Audio is not cached. Export encodes the whole cut's audio as one AAC stream with the music bed mixed under the voice, so the joins have no encoder delay or padding.
- Once a video is migrated, the pacing's cuts, zooms and overlays come from the [lock](#cutlock) instead of the take blocks: the timeline removes the union of the lock's `cut` instances from the kept ranges, and segments carry the lock's zooms and overlays next to a person's. The chunk hash then reads the same values from the lock. It adds the brand fields where something branded draws, font and Lottie files by content hash, the camera style where the camera shows and, at a chapter edge, both sides of the transition. Rule layer and element provenance are not part of it, like zoom provenance today. A video without a `cut.lock` is read from the take blocks as above. A chunk where a template other than `blur`, `bleep`, a b-roll clip or an empty slot draws adds the motion preset with its feel controls, the four brand colors and the content hash and weight of each font; one where a brand Lottie draws (a declared template, a re-skin or a `pop` sticker) adds that file's content hash, and one where a `chapter-band` without `text` draws adds the chapter's number and title. Every other chunk keeps its key when the brand changes. The lock's `music` and `sfx` instances play in the export's audio at their moments' output time, mixed with the music bed before the loudness pass.

## Overlay templates

An `overlay` node names a template, and the template owns its parameters ([0018](../decisions/0018-overlay-templates-as-typed-specs.md), [0023](../decisions/0023-motion-system-and-lottie-templates.md)). Each template is a typed spec in `shot-render`: parameter names, their kind (text, integer, boolean, time in microseconds) and which are required. A parameter of the wrong kind, an unknown one or a missing required one stops the export with the overlay's template and parameter. A spec only grows by optional parameters, and a renderer change bumps the renderer version without touching a spec, so a `cut.kdl` always reads the same.

Every template that draws moves on springs in the video's motion preset (the brand's `motion` node, by default reaction reactive, opinion editorial, product tour launch, tutorial calm) with the brand's feel controls, and draws in the brand's colors and fonts (by default the lime accent on dark cards, Geist and Geist Mono). Its parts come in one after another by the stagger, text in the preset's kinetic type, cards on frosted glass and tilting in the launch preset, with soft shadows that fall away from one light, motion blurred while they move. It also takes `enter` and `exit`: the microseconds its springs take to settle in after `from` and out before `to`, duration hints that fit the preset's springs. `blur` and `bleep` take neither and switch hard: a fade would reveal what they hide.

| Template | Parameters | What it does |
| --- | --- | --- |
| `link-card` | `url`, `accent` (bool) | A card for a link at the bottom left: GitHub pull request, issue or repository, a post on X, a Hacker News item, an npm package, or any link by its host. The rule places one from the word where a URL is said, written or spoken, for 6 s |
| `lower-third` | `text`, `subtitle` | A name or line at the bottom left |
| `highlight` | `x`, `y`, `width`, `height` (screen pixels), `text` | An accent box around text on the screen recording, following the layout and zoom. The rule places one where at least three words you say are on screen as you say them, read with Vision |
| `b-roll` | `file`, `start` (time) | A cutaway over the frame: a still (`.png`, `.jpg`) settling in with a slow push, a clip (`.mp4`, `.mov`) cut in hard from `start`, or a diff (`.diff`) typed out. The file is relative to the video folder. Without `file` it is an empty slot that draws nothing; the rule places slots over idle screen of at least 8 s and at every B marker |
| `code-diff` | `diff`, `highlight-line`, `highlight-at` (time) | A diff snapshot typed out, see the product tour example |
| `chapter-band` | `text`, `label` | The chapter's title on a band at the left as a chapter starts. Without `text` it shows the title of the chapter it opens, without `label` "Chapter" and the chapter's number |
| `end-card` | `text`, `subtitle`, `videos` (0 to 2), `subscribe` (bool) | The end screen over the brand's background: a headline ("Thanks for watching" by default) and frames where YouTube Studio places its elements, inside the inner 90% of the frame: up to two 16:9 videos, 36% of the width, stacked at the right, and the round subscribe button under the headline. Two videos and the button by default |
| `callout` | `x`, `y` (screen pixels), `width`, `height`, `text` | A ring on a point of the screen recording, or with `width` and `height` an outline around a box, with `text` on a label beside it towards the middle of the frame. Follows the layout and zoom. A rule copies `x` and `y` from a click or `x`, `y`, `width`, `height` and `text` from an OCR box; drawn by hand it snaps to the OCR box under the point or the nearest click within 160 screen pixels and 1.5 s |
| `pop` | `text`, `sticker`, `x`, `y`, `size` (4K output pixels) | An emoji or a word popping in, by default right of the middle in the upper third and 360 pixels tall. An emoji plays its animation from the bundled Noto set (👍 👏 😍 🥳 ✅ ✨ ❤️ 🔥 😂 👀 🎉, other emoji are refused), a word sits on an accent pill. `sticker` names a brand Lottie template drawn instead, its `text` slot set to `text`. One of `text` and `sticker` is required |
| `blur` | `x`, `y`, `width`, `height` (screen pixels), `strength` | The screen recording averaged over blocks of `strength` screen pixels (32 by default) inside the rectangle, following the layout and zoom |
| `bleep` | none | The voice over the range replaced by a 1 kHz tone |

A brand's `template` declarations ([brand.kdl](#brandkdl)) are templates too. A new name is a Lottie template: an overlay's parameters fill the slots of the same name (a `color` slot takes `"#rrggbb"`, a `time` slot microseconds), a color slot named `accent`, `text`, `card` or `background` defaults to the brand's color, and the composition draws over the whole frame, scaled to its width, from the overlay's start, holding its last frame. Declaring `link-card`, `lower-third`, `chapter-band` or `end-card` re-skins it: the overlay keeps the built-in parameters and the Lottie draws instead, its slots filled from what the template would show: `label`, `title`, `url` and `accent` for a link card, `text`, `subtitle` and `accent` for a lower third and an end card, `text`, `label` and `accent` for a chapter band. Declaring any other built-in name, or a slot the template does not fill, is an export error.

}

## Elements

`elements/<take>.jsonl` holds the facts of one take: [JSON Lines](https://jsonlines.org), one element per line, sorted by `t`. Analysis writes it while recording and after stop, `shot analyze --video <dir> --take <take>` rewrites it on request, and its diff is reviewed like any other. Builds read the file and never analyse ([0019](../decisions/0019-semantic-video-elements-and-style.md)).

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | string | one of the kinds below |
| `t` | integer | the start, in the take's media time in microseconds |
| `to` | integer | the end of a span. Required for span kinds, absent for moment kinds |
| `confidence` | integer | how sure the finding is, 0 to 100. Absent for a fact that is certain |
| `by` | string | the source and its version, for example `whisper@large-v3-turbo`, `vad@silero-5`, `events`, `claude` |
| attributes | | per kind, below. Text attributes are strings, the others integers |

An element is identified by its kind, its take and `t`. A re-cut never moves it. Two elements of one kind never share a `t`. A line with an unknown field, a kind with the wrong attributes or an element out of order is an error with its line number.

| Source | Kind | Spans | Attributes |
| --- | --- | --- | --- |
| Transcript | `word` | yes | `text` |
| | `sentence`, `silence`, `pause`, `retake`, `misspoken`, `emphasis` | yes | none |
| | `filler` | yes | `text` optional |
| Mentions | `url` | yes | `url`, `host` (`github`, `x`, `news.ycombinator`, `npm`, or the host name) |
| | `code` | yes | `text` |
| | `product` | yes | `name` |
| Screen | `click` | no | `x`, `y` in screen pixels |
| | `typing` | yes | `text` optional |
| | `idle` | yes | none |
| | `ocr` | yes | `text`, `x`, `y`, `width`, `height` |
| Camera | `face` | yes | `x`, `y`, `width`, `height` |
| | `expression` | yes | `label`, `strength` |
| Script | `chapter` | no | `text` optional, the title |

| Claude | `claim`, `punchline`, `aside`, `needs-source` | yes | none |

## Style rules

A rule selects elements and applies effects: `on <selector> { <effects> }`. Rules live in `brand.kdl`, `formats/<format>.kdl` and a video's `format.kdl`, after that file's other nodes. Selectors and effects are closed sets; an unknown one is an error with file, line and column.

### Selectors

`on <target> [attribute=value ...] [min=<time>] [confidence=<0..100>]`. The target is an element kind, or one of `chapter-start` (the first kept moment of each chapter), `chapter-end` (the last), `video-start` and `video-end`. Filters narrow it, written in this order: attributes of that kind that must equal the value (text bare when it is an id, otherwise quoted), `min` for span kinds, the shortest span the rule is about, and `confidence`, the lowest confidence; a fact without a confidence always passes. A filter the target does not have is an error. The selector is the rule's identity: one rule per selector in a file.

### Effects

Each child of a rule is one effect, one per key (the node, plus the template for overlays), written in this order. Defaults are left out when written.

| Effect | Properties | What it does |
| --- | --- | --- |
| `cut breath=<time> confidence=<0..100>` | both default 0 | Pacing. Removes the element's span, keeping `breath` on each side that borders material (none at the start of the take). An element less sure than `confidence` is not cut but listed in the lock's review queue. Breath is for gaps (silence, pause, idle); fillers and retakes are speech and are removed whole |
| `layout <layout>` | | The layout over the element's span |
| `zoom <percent> hold=<time> lead=<time>` | both default 0 | A punch-in from `lead` before the element to `hold` after its start or to its end, whichever is later, centered on the element's `x`, `y` when it has one |
| `overlay <template> for=<time> { ... }` | `for` required on moment targets | A template overlay over the element's span, or for `for` from its start. A child with a value is a literal parameter; a bare child names an attribute of the element to copy into the parameter of that name (`url`, `text`, `x`, `y`, `width`, `height`). Templates are the [overlay templates](#overlay-templates) and the brand's Lottie templates |
| `sfx <sound> gain=<dB>` | gain default 0, at most 0 | A sound at the element's start, looked up in the video's `sounds/`, then `brand/sounds/`, then the bundled set |
| `transition <kind> length=<time>` | length default 500 ms | How the chapter starting here joins the one before: `cut`, `dissolve`, `dip`, `stinger`, `mask-wipe` or `zoom-through`. Only on `chapter-start` and `video-start`, the join to the intro |
| `music "<file>" gain=<dB> duck=<dB>` | both required, at most 0 | A music cue starting at the element, until the next cue |
| `captions <style>` | | A caption style over the element's span |

`layout` and `captions` need a span, so they are an error on a moment target. An element in material the main cut does not keep gets no instances. A rule's results land in the [lock](#cutlock).

### Cascade

Layers apply lowest first: the brand's imports, `brand.kdl`, the channel's `formats/<format>.kdl`, the video's `format.kdl`. A rule replaces an earlier layer's rule with the same selector, whole. `on <selector> off` removes it. When several surviving rules give one element the same effect key, the selector with more filters wins; at equal count the later layer, then the later rule in its file. An [override](#overrides) in `cut.kdl` comes last and changes one element.

## `brand.kdl`

`brand/brand.kdl` holds the channel's look and sound ([0020](../decisions/0020-channel-brand-and-shared-styles.md), [0021](../decisions/0021-sound-transitions-and-bookends.md), [0023](../decisions/0023-motion-system-and-lottie-templates.md)). Every node is optional and appears once unless noted, in this order. The same grammar, without `import` and rules, is the `brand` block of a format layer; a later layer's fields replace the earlier ones field by field, so a video names only what differs.

| Node | Meaning |
| --- | --- |
| `import "<url>" rev="<commit>" style=<id>` | zero or more. A brand file read from the repo's `styles/<id>.kdl` at that commit, the lowest layer. The build records the commit in the lock. Imports are not followed further |
| `fonts heading=<font> body=<font> mono=<font>` | each optional. A bundled OFL font bare (`inter`, `geist`, `geist-mono`, `jetbrains-mono`) or a file in the repo by path, quoted, hashed by content |
| `colors accent= text= card= background=` | each optional, `"#rrggbb"` |
| `logo "<path>"` | an SVG or PNG in the repo |
| `sounds <key>=<sound> ...` | the sound for each automatic effect: a key is `zoom`, `card`, `click`, `transition` or `pop`, alone or with a phase `-travel`, `-impact`, `-settle` or `-exit`. The value is a sound name looked up like `sfx` |
| `intro bumper="<path>" title=<bool>`, `outro ...` | a bumper in `brand/media/` (ignored by git, missing is an export error), a generated title, or both |
| `end-card length=<time>` | the end card over the outro, or over the last seconds without one |
| `camera shape=<rounded,circle,square> corners=<px> border=<px> shadow=<none,soft,hard>` | how the camera is framed |
| `motion reaction=<preset> opinion=<preset> product-tour=<preset> tutorial=<preset>` | the motion preset of each format: `reactive`, `editorial`, `launch` or `calm` |
| `preset <name> tempo= bounce= density= stagger= beat-sync=<bool>` | one per preset, feel controls 0 to 100, each optional and defaulting to the preset's own, see [feel controls](#feel-controls) |
| `transition stinger="<path>" peak=<time>` | the Lottie stinger and the time its frame fully covers the picture, where the cut happens |
| `template <id> file="<path>" { slot <id> <text,color,integer,time> required=<bool> ... }` | a Lottie template with typed slots, the spec the renderer checks overlays against. Declaring a built-in template's name re-skins it |
| `on ...` | the channel's rules |

The lock lists every file the resolved brand names, by content hash, so a changed font or Lottie file changes the chunks it draws on. Font and Lottie paths are relative to the channel repo. This is the example channel's brand:

### Feel controls

Each control runs from 0 to 100 and maps to the springs every template moves on. Exits respond in 60% of the entrance's time, critically damped, and leave in the same order at half the stagger.

| Control | 0 | 100 |
| --- | --- | --- |
| `tempo` | entrance response 900 ms | 225 ms, halving every 50 |
| `bounce` | damping ratio 1, no overshoot | 0.4, about 25% overshoot |
| `density` | 30% of a template's travel, tilt and scale | 120% |
| `stagger` | parts move together | 120 ms between parts |

Each preset's own values, and what it does besides its springs:

| Preset | tempo | bounce | density | stagger | Text comes in | Cards |
| --- | --- | --- | --- | --- | --- | --- |
| `reactive` | 80 | 60 | 70 | 40 | word by word, popping past full size | pop in by scale |
| `editorial` | 60 | 20 | 60 | 50 | word by word, rising out of a mask | slide in |
| `launch` | 40 | 10 | 30 | 60 | glyph by glyph, rising | slide in on frosted glass, tilting up to 14 degrees |
| `calm` | 30 | 0 | 10 | 20 | word by word, fading | fade with a short slide |

## `cut.lock`

Every build writes `cut.lock` from the layers, `cut.kdl` and the elements, with no IO and no analysis, so two builds of the same files are byte-identical ([0025](../decisions/0025-lock-carries-the-resolved-style.md)). It is the input of the renderer and the chunk hash. Nobody edits it.

- `lock <version>` first. A build refuses a lock of another version.
- `import` nodes as in the brand, with the commit each was read at.
- `asset "<path>" hash="<blake3>"` for every file the resolved brand names, sorted by path.
- `brand { ... }`: the brand after the cascade, imports and rules removed.
- `take <id> { ... }` per take of the main cut, in cut order. Each child is one instance: the effect's node with its resolved values (`from`, `to` or `at`, `x`, `y`, a template's parameters as children), then its provenance: `on=<kind> t=<time>` names the element, `layer=` the layer, and either `rule="<selector>"` or, for an override, `override=<at>`. `review` instances are the queue: elements the pacing was not sure about, which play. `cut` instances may overlap, the timeline removes their union. Instances are sorted by start, then node, then template or sound. `orphan <kind> at=<time>` lists an override that found no element.

This is the example video's lock, built from the files above. The video's accent replaced the channel's, the import's `on chapter-start` rule lost to the brand's while its `on chapter-end` survived, the override at 22 s replaced the link card, the one at 45 s cut an unsure pause, the one at 9.8 s kept a filler so nothing of it appears, and the override in `t02` is an orphan.

## Migration of today's nodes

`shot migrate --video <dir>` turns a video written before the lock into the model above once, mechanically ([0024](../decisions/0024-content-stays-in-cut-kdl-style-moves-to-the-lock.md)). It runs analysis for every take without an elements file, then maps each take block node so the migrated video shows the same frames, and refuses to write anything when its timeline would differ from the old one:

| Today | After |
| --- | --- |
| `keep from= to=` and `remove ... by=manual` | stay as written. Adjacent kept ranges that were split only by a rule's removal merge into one |
| `remove from= to= by=<rule>` | dropped when the lock's cuts cover it. Otherwise `override <take> <kind> at=<element t> { cut }` on the queued element of that kind within 500 ms (C in the old queue), else kept as `remove ... by=manual`, the exact range |
| a lock cut that removes material the old cut kept | `override <take> <kind> at=<element t> { keep }` on its element |
| `review from= to= by=<rule>` | dropped: the queue is the lock's `review` instances |
| `ignore from= to= by=<rule>` | `override <take> <kind> at=<element t> { keep }` |
| `zoom ... by=<what>` | dropped when a rule's zoom equals it (scale, range, center). Otherwise `{ zoom <scale> hold=... lead=... }` on an element inside it whose point is its center (the trigger's kind, a `word` for `jump-cut` and `emphasis`), else kept as a person's zoom. A rule zoom the old cut did not have gets `zoom off` |
| `overlay link-card`, `highlight`, `b-roll` | dropped when a rule's overlay equals it. Otherwise `{ overlay <template> for=... { <params> } }` on an element of its kind starting with it, else kept as a person's overlay in its drawing order. A rule overlay the old cut did not have gets `overlay <template> off` |
| `auto-cut`, `auto-zoom`, `pacing` in `format.kdl` | a channel `formats/<format>.kdl` without rules gets the rules its settings stand for, the rules the shipped presets carry. The video's `format.kdl` keeps only the settings that differ from the channel's, its own rules where its settings stood for other rules, and `on <selector> off` for the channel's cut and zoom rules it never had |

Two choices keep the frames equal. A cut keeps its breath only on a side that borders kept material, so a silence that opens or ends the take's material goes whole there, as the pacing did. Chapter and video edges sit on the first and last moments the cuts leave. The jump-cut punch-in on every other cut has no rule, since a selector does not count (0019); migrated ones become overrides, new videos get none.

A migrated video has a `cut.lock`. `shot style build`, `shot export` and `shot check` rebuild it from the files unless the video shipped; the old rule commands (`shot autocut`, `shot autozoom`, `shot overlays find`) refuse a migrated video, and a build refuses a video whose `cut.kdl` still holds rule removals, review items or rule zooms.

## `script.md`

Markdown with a fixed shape, read line by line:

- `# <title>` is the first heading and appears once.
- `## <chapter>` starts a chapter.
- A bullet (`- ` or `* `) inside a chapter is a beat. Every `[label](target)` link in it is a source, usually a file in `sources/`. The prompter shows the bullet with links replaced by their labels.
- Any other text after a beat, indented or not, is that beat's full script for full-script mode. Lines in a paragraph join with spaces, paragraphs with a line break.
- Blank lines separate paragraphs. Other headings (`###` and deeper), text before the first beat of a chapter and beats before the first chapter are errors with a line number.

`shot-core` only reads this file. The script agent writes it as plain text.

```markdown
# Why we deploy on Fridays

## Hook

- Everyone says never deploy on a Friday. We do it every week. [the post](sources/never-friday.md)
  Everyone says never deploy on a Friday.
  We ship every single week, on Friday afternoon.

  And nothing burns.

## The rule everyone repeats

- Where the rule comes from, per [the article](sources/friday-article.md)
- Why it points at a slow rollback, see [the PR](https://github.com/coderscantina/shot-studio/pull/1) and [our notes](sources/rollback-notes.md)

## What we do instead

- Small diffs, feature flags, one-click rollback [notes](sources/rollback-notes.md)
```

## Take folder

`shot-capture` writes one folder per recording session, `media/<take>/`, named by its take id.

```
media/t03/
  screen.mp4    the display without the cursor: HEVC, display resolution, constant 60 fps
  camera.mp4    HEVC at the camera's format, when a camera was recorded
  mic.mp4       AAC 48 kHz mono, when a mic was recorded
  system.mp4    AAC 48 kHz stereo, when system audio was recorded
  events.jsonl  cursor and key events, see below
```

- **Take ids** are `t` and a number, at least two digits: `t01`, `t02`, ... `t100`. A new take gets the number after the highest take folder in `media/`, so an id is never reused while its folder exists, and a gap left by a deleted take is never filled. Deleting the newest take frees its id for the next recording. Cache keys hash the take's media identity as well as its id, so the new recording never reuses the old one's cache.
- **One clock.** Every track and the event log share the take's media time, 0 at session start. A track may begin a little after 0 when its device delivers its first sample late.
- **Fragmented MP4.** Each file is an initialization segment (`ftyp`, `moov`) followed by `moof` and `mdat` fragments of about 0.5 s, appended as they are encoded. Video has a keyframe every 0.5 s and no B-frames. A killed recording keeps every complete fragment and stays playable.
- A track that is missing was not recorded. Readers do not assume a camera or system audio.

## Cursor and key event log

Capture writes `media/<take>/events.jsonl` next to the take's tracks. The cursor is saved as events, not burned in, so zooms, click ripples, cursor size and the keystroke overlay are render settings.

The file is [JSON Lines](https://jsonlines.org): one JSON object per line, UTF-8, sorted by time, written as events happen so a crash keeps everything before it. Fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `t` | integer | media time in microseconds, on the same clock as the take's tracks |
| `kind` | string | `move`, `down`, `up`, `scroll`, `key` or `marker` |
| `x`, `y` | integer | cursor position in pixels of the screen track, origin top left. On every kind except `key` |
| `button` | string | `left`, `right` or `other`. On `down` and `up` |
| `dx`, `dy` | integer | scroll distance in pixels. On `scroll` |
| `key` | string | the key pressed, lowercase (`a`, `space`, `enter`, `tab`, `escape`, `left`, `f5`). On `key` |
| `mods` | array of strings | held modifiers from `cmd`, `shift`, `alt`, `ctrl`, `fn`, in that order. On `key`, may be empty |
| `mark` | string | the record hotkey pressed: `again` (A), `next` (N), `marker` (M), `zoom` (Z), `b-roll` (B) or `layout` (1 to 4). On `marker` |
| `beat` | integer | the beat the prompter shows after the press, numbered from 1 across the script. On `again` and `next` |
| `layout` | string | the layout chosen, one of the format's `layouts`. On `layout` |

Readers ignore fields they don't know, so capture can add fields without breaking them. A new `kind` is a change to this contract.

```json
{"t":0,"kind":"move","x":1920,"y":1080}
{"t":16667,"kind":"move","x":1932,"y":1074}
{"t":512000,"kind":"down","x":2210,"y":640,"button":"left"}
{"t":598000,"kind":"up","x":2210,"y":640,"button":"left"}
{"t":1200000,"kind":"scroll","x":2210,"y":900,"dx":0,"dy":-240}
{"t":2104000,"kind":"key","key":"p","mods":["cmd","shift"]}
{"t":2350000,"kind":"key","key":"enter","mods":[]}
{"t":4210000,"kind":"marker","x":2210,"y":640,"mark":"again","beat":2}
{"t":9800000,"kind":"marker","x":2210,"y":640,"mark":"next","beat":3}
{"t":12000000,"kind":"marker","x":1480,"y":910,"mark":"zoom"}
{"t":15500000,"kind":"marker","x":1480,"y":910,"mark":"layout","layout":"split"}
```

Markers are what the record hotkeys write. They are facts about the recording, so they live with it and carry the cursor position at the press, which is where "zoom here" points. They are not edit state: the rough cut turns them into `cut.kdl` nodes once, when the take is appended (see [`cut.kdl`](#cutkdl)), and milestone 07 covers `b-roll` markers with b-roll. A take folder without markers is a take recorded without the prompter.

`shot-board` implements these. It writes through refs and trees only, so a checked-out video branch's working tree goes stale after a board write.

- **Video branch**: `video/<slug>`. A card's state is read from its tip, falling back to the default branch for ideas without a branch yet. Moving a card is one commit on this branch, subject `🚚 move <slug> to <status>`.
- **Proposal branch**: `proposal/<slug>/<name>` off `video/<slug>`, holding commits that change the video's files. Paths are relative to the video folder. The diff is against the merge base with the video branch. Accept merges (fast-forward when possible), reject deletes the branch, and a conflicting accept changes nothing and lists the paths. See [0004](../decisions/0004-proposals-as-branches.md).
- **Release tag**: annotated CalVer `vYY.M.D` of the release date (`v26.11.7`), on the tip of a video branch whose status is `shipped`. A later release on the same day gets `.2`, `.3` and so on. Tags sort by their numeric parts. Message `🚀 ship <slug>`.

## Ship artifacts

`shot export`, `shot thumbnails` and `shot ship` write these into the video folder's `.shot/`, which git ignores. In git, a ship is the card in `shipped` and its release tag ([0022](../decisions/0022-ship-artifacts-outside-git.md)).

| Path | Written by | Holds |
| --- | --- | --- |
| `.shot/export/<cut>.mp4` | `shot export`, `shot ship`, the Edit and Ship screens | the rendered cut, `main` or a derived cut's name |
| `.shot/export/main.vtt` | export of the main cut | the caption sidecar |
| `.shot/export/main.png` or `main.jpg` | `shot thumbnails --pick`, the Ship screen | the main cut's thumbnail. Derived cuts have none |
| `.shot/ship/record.json` | `shot ship` | the upload record, below |
| `.shot/cache/thumbnails/`, `.shot/cache/ship/` | `shot thumbnails`, the Ship screen | thumbnail candidates and preview stills, safe to delete |

The title and description are not stored. `shot ship` drafts them from the project files on every run, as `shot describe` prints them: the title from `video.kdl`, then the hook beat of `script.md`, the chapters at their first spoken word and the links. A Short gets the hook and a link to the main video.

The upload record is JSON. Keys of `uploads` are cut names: `main` and each Short.

```json
{
  "uploads": {
    "main": {
      "video_id": "Ks-_Mh1QhMc",
      "size": 812345678,
      "privacy": "private",
      "thumbnail": true
    },
    "intro-hook": {
      "session": "https://www.googleapis.com/upload/youtube/v3/videos?uploadType=resumable&upload_id=AB",
      "size": 30123456,
      "privacy": "private",
      "thumbnail": false
    }
  },
  "release": "v26.11.7"
}
```

- `video_id` is set when an upload finished. A cut with one is never uploaded again.
- `session` is the resumable session of an unfinished upload of a file of `size` bytes. A run whose export has the same size continues it, otherwise it starts over.
- `release` is the tag, set once. Deleting the record makes the next run upload every cut again.
